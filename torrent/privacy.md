## 1. 요약

개발자는 사용자 데이터를 수집하지 않습니다.

개발자가 운영하는 별도의 서버가 없으며, 앱에서 개발자에게 데이터를 전송하는 네트워크 경로도 없습니다. 데이터는 사용자의 기기와 사용자가 직접 연결한 서버나 웹사이트 사이에서 오가며, 개발자는 이를 열람할 수 없습니다.

앱에는 광고가 없고 모든 기능이 무료입니다. 사용자를 추적하지 않으며 추적 허용(ATT)도 요청하지 않습니다. 앱 안의 인앱 구매는 개발 응원(선택 사항)뿐이며, Apple App Store가 결제를 처리합니다(§6.1).

## 2. 원칙

- **추적하지 않습니다.** 광고 · 분석 · 추적 SDK를 포함하지 않으며, 앱 추적 투명성(ATT) 권한을 요청하지 않습니다. 앱 코드는 광고 식별자(IDFA)나 기기 식별자를 읽지 않습니다.
- **분석 및 오류 보고 SDK를 사용하지 않습니다.** 제3자 분석 도구나 크래시 리포팅 라이브러리를 포함하지 않습니다.
- **개발자에게 전송되는 데이터는 없습니다.** 사용 기록, 기기 정보, 오류 보고, 결제 정보를 포함해 어떠한 데이터도 개발자에게 전송되지 않습니다.
- **사용자 데이터를 판매하거나 제3자와 공유하지 않습니다.** 개발자가 보유하는 사용자 데이터 자체가 없습니다.

## 3. 앱이 기기에 저장하는 것

### 3.1 iOS Keychain

앱은 민감한 정보를 안전하게 보관하기 위해 iOS Keychain을 사용합니다. 구체적인 저장 항목은 앱마다 다르며, 이 문서 뒤의 앱별 항목에서 안내합니다.

세 앱에 공통으로 적용되는 보호 방식은 다음과 같습니다.

- 접근성 속성은 `kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`로 설정되어 있습니다.
  - `ThisDeviceOnly`: 저장된 항목은 iCloud Keychain으로 동기화되지 않으며 기기 백업에도 포함되지 않습니다. 즉, 해당 기기 외부로 유출되지 않습니다.
  - `AfterFirstUnlock`: 기기를 재부팅한 뒤 한 번 잠금을 해제하면, 이후 화면이 잠긴 상태에서도 앱이 항목을 읽을 수 있습니다.
- 자격 증명과 인증서 신뢰 정보는 앱마다 분리된 전용 저장소에 보관됩니다. 각 앱은 고유한 Keychain 접근 그룹을 사용하므로 다른 앱의 비밀번호, 계정 정보, 인증서 신뢰 내역을 읽을 수 없습니다.
- iOS의 특성상 앱을 삭제하더라도 Keychain 항목이 자동으로 삭제되지 않을 수 있습니다. 저장된 계정 정보를 확실히 지우려면 앱을 삭제하기 전에 앱 내 설정에서 먼저 삭제해 주시기 바랍니다(§9).

### 3.2 앱 환경설정 (UserDefaults)

화면 모드(라이트/다크), 목록 정렬 방식, 표시 옵션 등 일반 설정값은 기기의 표준 저장소(UserDefaults)에 보관되며 해당 앱에서만 접근할 수 있습니다.

### 3.3 기기 안의 파일

앱이 생성하거나 사용자가 저장한 파일은 기기 내부(앱 샌드박스 또는 동일 개발자의 앱 간 공유 저장 공간)에 보관됩니다. 공유 저장 공간 사용 여부는 앱별 항목에서 설명합니다. 앱은 파일 정렬 및 표시, 진단 로그 파일 관리를 위해 앱 컨테이너 내부 파일의 생성일과 수정일을 읽습니다.

1. **사용자가 설정한 Synology NAS**: 로그인, 작업 목록 조회, 작업 추가·일시정지·재개·삭제를 위해 통신합니다. 주소는 사용자가 직접 입력하거나 QuickConnect ID를 통해 연결합니다. QuickConnect를 사용하는 경우에 한해 접속 주소를 확인하는 과정에서 Synology의 QuickConnect 서비스에 접속합니다.
2. **사용자가 앱 내 브라우저로 직접 접속한 웹사이트**: 사용자가 주소창에 직접 입력한 주소로만 연결됩니다. 앱은 시작 페이지에 특정 사이트를 미리 설정해 두지 않으며, 사이트 목록이나 추천 기능도 제공하지 않습니다. 주소창에 검색어를 입력하면 사용자가 설정에서 선택한 검색 엔진(Google, DuckDuckGo, Bing)으로 이동합니다.

이 앱은 영상이나 음악 같은 콘텐츠 파일을 직접 내려받지 않습니다. 앱이 직접 받아오는 데이터는 NAS에 전달할 `.torrent` 메타데이터 파일(보통 수십 KB 크기)뿐이며, 이 또한 대상 사이트에 로그인이 필요해 NAS가 직접 파일을 가져올 수 없는 경우에만 동작합니다. 받아온 `.torrent` 파일은 즉시 사용자의 NAS로 전송되며 기기에 남거나 제3자에게 전달되지 않습니다. 실제 파일 다운로드는 사용자의 NAS에 설치된 Download Station에서 수행합니다.

개발자가 운영하는 별도의 서버는 없습니다.

### D. 앱이 요청하는 권한

이 앱이 요청하는 권한은 다음 한 가지입니다.

- **로컬 네트워크 접근**: 사용자의 NAS가 동일한 내부 네트워크(사설 IP 대역)에 있을 때 iOS에서 한 번 권한을 요청합니다. 앱은 주변 기기를 검색하거나 스캔하지 않으며, 사용자가 NAS 설정에 직접 입력한 주소로만 연결합니다.

사진, 카메라, 마이크, 위치, 연락처, 알림, 건강, 캘린더, 추적(ATT) 등의 권한은 요청하지 않으며, 앱의 `Info.plist`에 해당 권한 키가 없고 관련 API도 호출하지 않습니다.

### E. 서드파티 라이브러리

이 앱은 외부 오픈소스 라이브러리를 사용하지 않으며, 앱 내 설정 > 오픈소스 라이선스 화면에서도 동일하게 안내하고 있습니다.

광고 SDK, 제3자 분석 SDK, 크래시 리포팅 도구도 사용하지 않습니다.

### G. 평문 HTTP 를 쓰는 경우와 그 이유 (본문 §7)

이 앱에서 암호화되지 않은 평문 HTTP로 연결하는 경우는 다음 두 가지뿐입니다.

1. **NAS에서 HTTPS를 사용하지 않을 때**: 가정용 NAS는 주로 내부 네트워크(LAN)에서 운영되며, Synology DSM의 기본 설정은 평문 HTTP(포트 5000)입니다. 사용자가 NAS에서 HTTPS를 활성화하지 않은 경우 HTTP로 연결하며, HTTPS를 설정한 경우에는 임의로 보안 수준을 낮추지 않고 HTTPS로 연결합니다.
2. **앱 내 브라우저로 접속한 웹사이트가 HTTP만 지원할 때**: 내장 브라우저는 사용자가 원하는 웹사이트에 자유롭게 접속할 수 있는 일반 브라우저이므로, 아직 HTTPS를 지원하지 않는 웹사이트에도 연결할 수 있도록 허용합니다.

두 경우 모두 통신 상대는 사용자가 직접 주소를 입력한 개인 NAS이거나 직접 접속한 웹사이트이며, 개발자에게 전송되는 연결은 없습니다. 검증에 실패한 인증서는 사용자가 해당 호스트를 직접 신뢰하기로 승인하기 전까지 차단되며, NAS와 브라우저의 인증서 신뢰 정보는 §A에 설명된 별도의 저장소에 각각 분리되어 보관됩니다.

### H. 암호화와 수출 규정 (본문 §7)

이 앱은 운영체제에서 기본 제공하는 표준 HTTPS(TLS) 암호화만 사용합니다. 따라서 미국 수출관리규정(EAR) Category 5 Part 2의 표준 암호화 면제 대상에 해당하며, App Store 앱 정보에도 이에 따라 선언되어 있습니다(`ITSAppUsesNonExemptEncryption = false`).
