# 개인정보 처리방침

**적용 대상**: Easy Web Image Collector (iOS)
**최종 수정일**: 2026-10-21 **버전**: 1.2

---

## 1. 요약

**개발자는 사용자 데이터를 수집하지 않습니다.**

개발자가 운영하는 서버가 존재하지 않고, 앱이 개발자에게 요청을 보내는 네트워크 경로가
없습니다. 사용자의 데이터는 **사용자의 기기**와 **사용자 본인이 소유·설정한 서버**
사이에서 움직입니다. 개발자는 그 데이터를 볼 수 없습니다.

다만 이 앱은 무료로 제공하기 위해 **Google AdMob 광고**를 보여 줍니다. 광고를 불러오는 과정에서
앱에 들어 있는 Google 의 광고 SDK 가 일부 기기 데이터를 **Google 에 직접** 보냅니다(§6.1).
앱은 iOS 의 **추적 허용(ATT)** 을 한 번 묻습니다. **허용한 경우에만** 맞춤 광고를 위해 광고 식별자(IDFA)가
Google 에 제공되고, 허용하지 않으면 **비개인화 광고만** 요청합니다(§6.1).
광고를 없애는 **인앱 구매**는 Apple 의 App Store 가 처리합니다(§6.2).

## 2. 원칙

- **추적은 사용자가 허용할 때만입니다.** 앱은 앱 추적 투명성(ATT) 권한을 한 번 묻습니다. 사용자가
  **허용하면** 광고 SDK 가 광고 식별자(IDFA)를 써서 맞춤 광고를 요청하며, 이는 Apple 의 정의상
  **추적**에 해당합니다. **허용하지 않으면**(거부 · 미결정 · 제한) IDFA 는 제공되지 않고 모든 광고 요청을
  **비개인화**(`npa=1`)로 보냅니다. 앱 자신의 코드는 광고 식별자나 기기 식별자를 읽지 않습니다.
  선택은 언제든 **iOS 설정 › 개인정보 보호 및 보안 › 추적** 에서 바꿀 수 있습니다.
- **분석 · 크래시 리포팅 SDK 가 없습니다.** 제3자 분석 SDK 와 제3자 크래시 리포팅 라이브러리를
  탑재하지 않습니다. 탑재한 광고 SDK 는 **Google Mobile Ads SDK**(동의 관리용 User Messaging
  Platform 포함) 하나이며, 그것이 처리하는 데이터는 §6.1 에서 밝힙니다.
- **개발자에게 오는 데이터가 없습니다.** 사용 기록, 기기 정보, 오류 보고, 구매 정보를 포함해
  어떤 데이터도 개발자에게 전송되지 않습니다.
- **개발자는 사용자 데이터를 판매하거나 제3자와 공유하지 않습니다.** 개발자가 가진 사용자 데이터가
  애초에 없습니다. 광고 SDK 가 Google 에 직접 보내는 데이터는 §6.1 이 다룹니다.

## 3. 앱이 기기에 저장하는 것

### 3.1 iOS Keychain

앱은 iOS Keychain 을 사용합니다. 저장되는 항목은 앱마다 다르며, 그 목록은
이 문서 뒤에 이어지는 **앱별 항목**에서 밝힙니다.

세 앱에 공통으로 적용되는 보호 방식은 다음과 같습니다.

- 접근성 속성은 **`kSecAttrAccessibleAfterFirstUnlockThisDeviceOnly`** 입니다.
  - `ThisDeviceOnly` — 이 항목은 **iCloud Keychain 으로 동기화되지 않고**,
    기기 백업에도 포함되지 않습니다. 기기를 벗어나지 않습니다.
  - `AfterFirstUnlock` — 재부팅 후 최초 잠금 해제 이후에는 화면이 잠긴 상태에서도
    앱이 읽을 수 있습니다.
- **자격 증명과 인증서 신뢰는 앱마다 독립된 저장소**에 있습니다. 각 앱은 자기 전용 Keychain
  접근 그룹에 쓰므로, 한 앱이 다른 앱의 비밀번호 · 계정 · 인증서 신뢰를 읽을 수 없습니다.
- **예외는 하나, 광고 제거 구매 기록입니다.** 한 앱에서 광고 제거를 사면 같은 기기의 다른 두 앱에서도
  광고가 사라지도록, 세 앱이 함께 읽는 공유 접근 그룹(`com.jjsuite.shared`)에 앱마다 항목을 하나씩
  둡니다. 담기는 것은 **광고 제거 상태(없음 · 만료일 · 영구)와 갱신 시각뿐**이며, 결제 정보 · Apple ID ·
  영수증은 담기지 않습니다. 이 공유는 같은 기기에 설치된 같은 개발자의 앱 사이에서만 일어납니다.
- iOS 는 앱을 삭제해도 Keychain 항목을 함께 지운다고 보장하지 않습니다. 저장된 자격 증명을 확실히
  지우려면 앱을 삭제하기 **전에** 앱 안에서 지워 주세요(§9). 광고 제거 기록은 앱을 지워도 남아 다른 두 앱에
  계속 적용됩니다.

### 3.2 앱 환경설정 (UserDefaults)

외관(라이트/다크), 목록 정렬, 표시 옵션 같은 설정값은 기기 안의 표준 저장소
(UserDefaults)에 저장됩니다. 앱 자신만 접근할 수 있습니다. 광고 동의 상태(§6.1)도
Google 의 동의 SDK 가 이 저장소에 기록합니다.

### 3.3 기기 안의 파일

앱이 만들거나 사용자가 저장한 파일은 **기기 안**에 있습니다 — 앱 샌드박스, 또는 앱에 따라
같은 개발자의 앱끼리 함께 쓰는 공유 저장 공간(**앱별 항목**에서 밝힙니다). 앱은 파일 정렬과 표시,
그리고 진단 로그 파일 회전을 위해 **자기 컨테이너 안의 파일 시각(생성일·수정일)** 을 읽습니다.

## 4. iCloud 로 나가는 것 — 설정값뿐입니다

앱은 Apple 의 **iCloud Key-Value 저장소**를 사용해 **일부 설정값**을 사용자 본인의
다른 기기와 동기화합니다.

- 동기화되는 것은 **설정값**입니다: 토글(켬/끔), 선택지(예: 외관 · 검색 엔진),
  숫자값, 기본 폴더 경로 문자열, 활성 프로필 식별자(UUID).
- 동기화되지 **않는** 것: **비밀번호를 포함한 모든 자격 증명**, 사진·동영상·문서 등
  파일의 내용, 방문 기록, 즐겨찾기, 진단 로그, 광고 제거 구매 기록, 광고 동의 상태.
- **저장소는 앱마다 독립**입니다. 세 앱이 서로의 값을 덮어쓰지 않습니다.
- 이 동기화는 **Apple 이 운영**합니다. 데이터는 사용자의 iCloud 계정 안에 있고
  **개발자는 접근할 수 없습니다.**
- 앱 안에 이 동기화를 켜고 끄는 토글은 없습니다. iOS 설정에서 앱의 iCloud 사용을
  끄면 동기화도 멈춥니다.

동기화되는 키의 정확한 목록과 개수는 앱마다 다르며, **앱별 항목**에서 밝힙니다.

## 5. 진단 로그

앱은 문제 해결을 위해 **기기 안에** 진단 로그를 남깁니다.

- 저장 위치: 앱 컨테이너의 `Documents/diagnostics/` (세션별 텍스트 파일, 최근 10개만 유지).
- 이 로그는 **자동으로 전송되지 않습니다.** 사용자가 설정 화면에서 직접 공유 시트로
  내보낼 때만 기기를 떠납니다.
- 로그에 담길 수 있는 것: 동작 시각과 결과, 오류 메시지, 앱이 접속한 서버의 주소와
  요청 경로, 실패한 요청의 대상 주소. 세션 시작 시 기기 모델명 · iOS 버전 · 앱 버전이
  한 줄 기록됩니다(문제 재현을 위한 값이며, 기기를 식별하는 고유 번호는 아닙니다).
- 로그에 담기지 **않는** 것: 비밀번호, 2단계 인증 시드. 서버 세션 키는 기록 전에
  마스킹됩니다.

진단 로그를 지원 문의에 첨부할 때는 **위 내용이 함께 전달된다는 점**을 알고 보내 주세요.
필요하면 첨부하지 않고 문의해도 됩니다.

## 6. 앱이 통신하는 상대

앱이 여는 네트워크 연결의 상대는 **사용자가 지정하거나 사용자가 직접 연 곳**, 그리고
아래 두 서비스입니다 — 광고를 위한 **Google**(§6.1)과 광고 제거 구매를 위한 **Apple App Store**(§6.2).
사용자가 지정하는 상대의 목록은 앱마다 다르며 **앱별 항목**에서 밝힙니다.

공통으로 참인 것: **개발자가 운영하는 서버는 존재하지 않습니다.** 앱은 개발자에게
어떤 요청도 보내지 않습니다.

### 6.1 광고 — Google AdMob

- **언제 나오나**: 앱이 일을 하는 동안 사용자가 기다릴 때만 — 예를 들어 서버 접속, 파일 전송, 작업 추가.
  진행 창 안에 「광고」 표시가 붙은 300×250 배너가 최소 2초 보입니다. **앱을 열 때 나오는 광고와 일정 시간마다
  나오는 광고는 없고**, 앱을 연 뒤 5초 동안도 나오지 않습니다. 광고 제거를 구매했거나, 광고 동의가 정해지지
  않았거나, 받아 둔 광고가 없으면 진행 창은 진행 상태만 보여 줍니다.
- **추적 허용(ATT)과 맞춤 광고**: **처음 실행할 때**, 광고 동의 확인(아래)이 끝난 뒤 앱이 화면에 있을 때
  iOS 의 추적 허용 창을 **한 번** 띄우고, 다시 묻지 않습니다.
  - **허용**하면 광고 식별자(IDFA)가 Google 에 제공되고, 관심사와 다른 회사의 앱 · 웹사이트에서의 활동에
    기반한 **맞춤 광고**가 나올 수 있습니다. 이것은 Apple 의 정의상 **추적**입니다.
  - **허용하지 않으면**(또는 기기 설정으로 제한되어 있으면) IDFA 는 제공되지 않고 모든 광고 요청에
    비개인화 표시(`npa=1`)를 붙입니다.
  - 어느 쪽을 골라도 앱의 기능과 광고 횟수는 같습니다. 선택은 언제든
    **iOS 설정 › 개인정보 보호 및 보안 › 추적** 에서 이 앱의 스위치로 바꿀 수 있습니다.
- **동의**: 앱을 시작할 때 Google 의 User Messaging Platform 으로 동의가 필요한 지역인지 확인하고,
  유럽경제지역(EEA) · 영국 등에서는 광고를 요청하기 **전에** Google 의 동의 양식을 보여 줍니다.
  동의가 확인되지 않으면 광고를 요청하지 않습니다. 동의는 **설정 → 광고 제거 → 광고 개인정보 설정**
  에서 언제든 바꿀 수 있습니다(이 항목은 동의가 필요한 지역에서만 보입니다).
- **Google 이 처리할 수 있는 데이터** (Google 이 AdMob 에 대해 공개한 기준):
  기기 식별자, 광고 데이터(어떤 광고를 보고 눌렀는지), 제품 상호작용(앱 실행 · 탭 등),
  대략적인 위치(IP 주소에서 추정), 진단 정보(성능 · 오류). 용도는 광고 게재와 측정, 부정 클릭 방지
  같은 **광고 목적**과, Google 의 분석 · 광고 성과 측정입니다. 이 중 **기기 식별자는 추적에 쓰일 수 있고**
  (추적을 허용한 경우의 IDFA), 대략적 위치 · 광고 데이터 · 제품 상호작용 · 기기 식별자는 Google 쪽에서
  사용자와 연결될 수 있습니다. 추적을 허용하지 않으면 IDFA 는 제공되지 않습니다.
- 이 데이터는 앱 안의 Google SDK 가 **Google 서버로 직접** 보냅니다. 개발자 서버를 거치지 않으며,
  개발자는 개별 사용자의 데이터를 받지 않습니다. 개발자가 AdMob 에서 볼 수 있는 것은 노출 수 · 수익 같은
  **집계 보고서**뿐입니다.
- 광고를 누르면 광고주의 웹사이트나 App Store 페이지가 열립니다. 그 뒤의 처리는 그 사이트의 방침을 따릅니다.
- Google 의 처리는 Google 의 방침을 따릅니다:
  [Google 개인정보처리방침](https://policies.google.com/privacy) ·
  [Google 이 파트너 사이트 · 앱의 데이터를 사용하는 방식](https://policies.google.com/technologies/partner-sites).

### 6.2 광고 제거 구매 — Apple App Store

- 광고를 없애는 상품 세 가지를 앱 안에서 팝니다: **1개월 · 1년**(비갱신 — 자동으로 결제되지 않습니다)과
  **영구**(한 번 구매).
- 결제는 **Apple 이 App Store 에서 처리**합니다. 앱과 개발자는 카드 번호 같은 결제 정보나 Apple ID 를
  받지 않습니다. 구매자를 식별하는 정보는 개발자에게 전달되지 않습니다.
- 앱은 기기에 있는 이 앱의 구매 기록(어떤 상품을 언제 샀는지, 환불되었는지)을 Apple 의 StoreKit 으로 읽어
  광고 제거 기간을 계산하고, 그 **결과(상태와 만료일)만** §3.1 의 공유 Keychain 항목에 저장합니다.
- **구매 복원**을 누르면 App Store 와 동기화해 구매 기록을 다시 받아 옵니다.

## 7. 보안

- **암호화된 연결을 우선 사용합니다.** 서버와의 통신은 가능한 경우 표준 HTTPS(TLS)로
  이루어집니다.
- **평문 HTTP 가 필요한 경우가 있고, 그때는 차단하지 않습니다.** 세 앱 모두
  `NSAllowsArbitraryLoads = true` 를 선언하므로, 상대가 HTTP 만 제공하면 평문으로
  연결됩니다. 어떤 경우에 그렇게 되는지와 그 이유는 **앱별 항목**에서 밝힙니다.
  어느 경우든 연결 상대는 사용자가 직접 연 웹사이트이거나 사용자가 주소를 입력한
  본인 소유 서버이며, 개발자에게 가는 연결은 없습니다(§6).
- 앱은 표준 암호화(TLS, 앱에 따라 SSH · SMB 3)만 쓰며, 미국 수출 규정과 Apple 요구에 따라 App Store
  앱 정보에서 수출 규정 질문에 답합니다. 앱마다 어떻게 답했는지는 **앱별 항목**에서 밝힙니다.
- 자격 증명은 §3.1 의 방식으로 iOS Keychain 에 보관됩니다.
- 사용자가 명시적으로 신뢰를 승인한 호스트에 한해, 그 인증서의 지문을 저장해 다음
  접속에서 대조합니다. 승인하지 않은 호스트의 인증서 오류는 그대로 차단됩니다.

## 8. 어린이 개인정보 (COPPA)

개발자는 13세 미만 어린이를 포함해 **누구로부터도 개인정보를 수집하지 않습니다.**
앱은 어린이를 대상으로 만든 앱이 아닙니다. 맞춤 광고는 추적을 허용한 경우에만 요청하고, 그렇지 않으면
비개인화 광고만 요청합니다.

| 권한 | Info.plist 키 | 실제 용도 |
|---|---|---|
| 사진 — **추가 전용** | `NSPhotoLibraryAddUsageDescription` | 이미지 뷰어에서 **사진 앱에 저장**을 누를 때만 묻습니다. 그 이미지 한 장을 사진 보관함에 추가합니다. **사진 보관함을 읽지 않습니다** — 읽기 권한 키가 없습니다 |

**임의 웹사이트 접속 허용(ATS 완화)에 대하여** — 이 앱은 `NSAllowsArbitraryLoads` 를
켜 둡니다. 사유는 하나입니다: **범용 브라우저라서 사용자가 어떤 사이트든 열 수 있어야
하고, 그중에는 아직 HTTPS 를 쓰지 않는 사이트가 있습니다.** 개발자 서버나 사설 장비를

본문 §7 이 말하는 "평문 HTTP 가 필요한 경우"는 이 앱에서는 **이 한 가지뿐입니다** —
사용자가 연 HTTP 웹사이트. 개발자 쪽으로 나가는 평문 통신은 애초에 존재하지 않습니다.
